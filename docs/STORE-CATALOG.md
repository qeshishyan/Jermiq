# Խանութի կատալոգն ու պատվերների կառավարումը

Վերափոխումը հիմնված է `master`-ի `0256b27` տարբերակի վրա։ Գործող ապրանքները, հայտերը, հաշիվները և լուսանկարները պահպանվում են։ Ten-Shop-ի կառուցվածքը հարմարեցված է Jermiq-ին․ ռուսական կոնտակտներ, գներ կամ չհաստատված մոդելների համատեղելիություն չեն ներմուծվում։

## Ադմինի աշխատանքը

- `/admin/store`՝ կատեգորիաների ծառ, հերթականություն, նկարներ, հրապարակում, սարքի բրենդ/սերիա/մոդել, գլխավոր էջի առաջարկ, լուսանկարով օգնություն, մեծածախ առաջարկ, վճարման և ընկերության մասին տեքստեր։
- `/admin?section=products`՝ գործող ապրանքի խմբագրիչ՝ կատեգորիա, արտիկուլ, արտադրող, փոխարինման կոդեր, գին/հին գին, առկայության քանակ, համատեղելի մոդելներ, փոխարինողներ, հարակիցներ և հավաքածուի ապրանքներ։ «Առաջարկվող» և «Նոր» նշումները կառավարում են գլխավորի ցանկերը։
- `/admin/orders`՝ կայքից գրանցված պատվերներ, ապրանքային ու գնային պատճեններ, որոնում, էջավորում և կարգավիճակներ։ Հասանելի է ադմինին և օֆիսի աշխատակցին։
- `/admin/reviews`՝ կարծիքների հաստատում/մերժում։ Հանրային էջում հայտնվում են միայն հաստատված կարծիքները։
- Գործող կոնտակտները, ժամերը, առաքումն ու երաշխիքը խմբագրվում են հիմնական ադմինի կարգավորումների բաժնից։ Նոր կատեգորիաների և գլխավորի տեքստերը թարգմանվում են գործող «Լեզուներ և տեքստեր» բաժնում։

Նախ ստեղծեք իրական մոդելը, ապա ապրանքի խմբագրիչից ընտրեք դրա համատեղելիությունը։ Մասի արտադրողը, վաճառքի բրենդը և համատեղելի սարքի բրենդը տարբեր դաշտեր են։ Համապատասխանությունը հաստատեք մատակարարի տվյալներով և չափերով։

Կատեգորիան կամ մոդելը հեռացնելը մերժվում է, եթե ապրանքները դեռ հղվում են դրան։ Կարելի է անջատել հրապարակումը։ Չհրապարակված ծնողի ենթաբաժիններն ու դրանց ապրանքներն ավտոմատ թաքցվում են։ Հնացած խմբագրումը պահելիս ցուցադրվում է հակասություն․ նախ վերաբացեք տվյալները։

## Հանրային էջեր

`/catalog`-ը ամբողջ տեսականին է, `/parts`-ը՝ պահեստամասերը։ Կատեգորիան ընտրվում է `category` պարամետրով։ Աջակցվում են `q`, `brand`, `model`, `min`, `max`, `sort`, `pageNumber` և կրկնվող `spec=բանալի:արժեք` ֆիլտրեր։ Ֆիլտրերն աշխատում են սերվերում և պահպանվում հղման մեջ։ Տեխնիկական ֆիլտրերը ստացվում են տվյալ բաժնի ապրանքների բնութագրերից։

`/selection`-ը սարքի մոդելով ընտրությունն է։ Սկզբնական մոդելների ցանկը դատարկ է՝ չհաստատված համատեղելիություն չհրապարակելու համար։ Մինչ տվյալների լրացումը հասանելի է լուսանկարով օգնությունը։

`/favorites`, `/compare`, `/cart` էջերը պահում են ընտրված ապրանքների կոդերը տվյալ բրաուզերում։ Համեմատությունը ցույց է տալիս նաև ապրանքների տեխնիկական բնութագրերը։ Փակված կամ հեռացված ապրանքները ցանկերի բեռնելիս հեռացվում են։

`/delivery`, `/payment`, `/about` էջերն օգտագործում են ադմինից խմբագրվող բովանդակությունը։ Ապրանքի կարծիքները հասանելի են `/products/{slug}/reviews` հասցեով։

## Պատվերների հոսք

`POST /api/orders`-ը ընդունում է միայն ընտրված ապրանքների կոդերն ու քանակները և կոնտակտային/ստացման տվյալները։ Գներն ու առկայությունը ստուգվում են սերվերում։ Ստեղծվում են անփոփոխ ապրանքային տողեր և գործող օֆիսի պատվերի հայտ/ծանուցում՝ մեկ transaction-ով։ Կրկնակի նույն հարցումը չի ստեղծում երկրորդ պատվեր։

Գինը չլրացված կամ կողմնորոշիչ լինելու դեպքում վերջնական գումարը չի ներկայացվում որպես հաստատված։ Առաքման արժեքը համաձայնեցվում է մենեջերի հետ։ Այս իրականացումը քարտից գումար չի գանձում, վճարային դարպաս կամ առաքման ընկերության ավտոմատ API չի միացնում։ Պահեստի քանակը սահմանափակում է պատվերի քանակը, բայց ավտոմատ ամրագրում/դուրսգրում չի կատարվում։

Պատվերի կարգավիճակի հիմնական աղբյուրը `/admin/orders`-ն է։ Դրանից կատարված փոփոխությունը փոխանցվում է նաև հայտի վիճակին և պատմությանը։ Օֆիսի ընդհանուր հայտային վիճակները և պատվերի փուլերը տարբեր բառարաններ ունեն։

## Պահպանում և տեղադրում

Կատալոգի կառուցվածքը պահվում է գործող `Settings` աղյուսակի `store-catalog` գրառման մեջ, պատվերների պատճենները՝ `order:{id}`, կարծիքները՝ `review:{id}` գրառումներում։ Լրացուցիչ DB migration անհրաժեշտ չէ։ Գործարկման սկզբում կատալոգը ստեղծվում է մեկ անգամ և եղած ապրանքներին նշանակվում են նախնական բաժիններ։ Հետագա վերագործարկումները չեն վերագրում խմբագրումները։

Սկզբնական 70 կատեգորիաները կարելի է թաքցնել կամ վերադասավորել ըստ իրական տեսականու։ Գործող 55 սկզբնական ապրանքները պահպանվում են։ Նրանց մեջ կան ցուցադրական կամ չհաստատված տվյալներով գրառումներ․ իրական վաճառքից առաջ ստուգեք գները, նկարները, արտիկուլները և համատեղելիությունը։

Տեղադրումից առաջ պահուստավորեք ամբողջ տվյալների պանակը։ Նոր էջերի համար պետք է տեղադրել նաև նոր CSS/JavaScript և seed ֆայլերը։ Հին `/catalog`, `/parts`, `/products/{slug}` հասցեները պահպանվում են։

## Ստուգումներ

```bash
dotnet build Jermiq.sln -c Release
python3 tests/smoke_test.py --frontend
JERMIQ_FRONTEND_TESTS=1 python3 tests/backoffice_test.py
python3 tests/store_catalog_test.py --frontend
python3 tests/store_orders_test.py
python3 tests/product_reviews_test.py
```

Թեստերը գործարկվում են ժամանակավոր բազաներով և պատահական թեստային հաշիվներով։ Կոնկրետ կատարված ստուգումների արդյունքները նշվում են աշխատանքն ավարտելու հաղորդագրությունում․ այս հրամանների ցանկն ինքնին չի նշանակում, որ բոլորը տվյալ միջավայրում անցել են։
